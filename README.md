# Velora

Velora is an open-source Roblox account mirror. It uses Roblox Quick Login only to verify which account approved a short-lived code, then reads non-secret/public account information and renders it in a clean profile view.

**Velora deliberately does not perform the final Quick Login session exchange and never obtains or stores a `.ROBLOSECURITY` cookie.**

> Unofficial project. Velora is not affiliated with Roblox Corporation.

## What it mirrors

- Roblox user ID
- username and display name
- verified badge state
- public description
- account creation date
- public account state
- avatar headshot
- friends, followers, following and group counts when available
- public group memberships/roles when available

Velora does not expose passwords, authentication cookies, access tokens, private keys, email addresses, phone numbers, or other private account data.

## How the Quick Login flow is handled

1. The server requests a short-lived Quick Login challenge from Roblox.
2. Only the six-character code and expiration are returned to the browser.
3. Roblox's `privateKey` stays server-side inside an AES-256-GCM encrypted, HttpOnly, SameSite cookie.
4. Velora polls the Quick Login status endpoint.
5. When the challenge becomes `Validated`, Velora uses the returned account name to resolve public profile data.
6. The encrypted challenge cookie is immediately destroyed.
7. Velora **never** calls Roblox's final login endpoint and therefore never creates a Roblox authenticated session.

Roblox Quick Login is an undocumented/internal API and can change without warning. Roblox recommends Open Cloud/OAuth for supported production integrations.

## Local development

Requirements: Node.js 20.9+.

```bash
npm install
cp .env.example .env.local
```

Generate a secret:

```bash
openssl rand -base64 48
```

Put the result in `.env.local` as `VELORA_SESSION_SECRET`, then run:

```bash
npm run dev
```

Open `http://localhost:3000`.

## Deploying to Vercel

1. Import this GitHub repository into Vercel.
2. Add an environment variable named `VELORA_SESSION_SECRET` with a long random value (at least 32 characters).
3. Deploy. No other services or databases are required for v0.1.

The encrypted challenge is stateless and stored only in the user's HttpOnly cookie, which makes the flow compatible with Vercel serverless functions without a database.

## Security model

- challenge private key is never returned to client JavaScript
- challenge state is encrypted with AES-256-GCM
- cookie is HttpOnly, SameSite=Strict and Secure in production
- state expires with the Roblox Quick Login challenge
- state is deleted immediately after validation/cancellation/expiration
- API handlers reject cross-origin browser requests
- no Roblox session cookie or token is generated by Velora
- no database and no server-side account storage in v0.1
